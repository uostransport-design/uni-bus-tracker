# 🚌 University of Sharjah — Live Bus Tracking Platform
### منصة تتبع حافلات جامعة الشارقة المباشرة

منصة كاملة لتتبع حركة حافلات النقل الداخلي في الجامعة لحظيًا، بشاشة عرض عامة ثنائية اللغة (عربي/إنجليزي) مناسبة لمحطات الانتظار، تطبيق ويب للسائقين، ولوحة إدارة شاملة بأدوار متعددة.

---

## ⚠️ ملاحظة صادقة حول نطاق التنفيذ

طلبك الأصلي يتضمن مواصفات منصة ضخمة (Next.js + TypeScript + NestJS + PostgreSQL + Docker + MQTT + إلخ). قررت بناء نفس **الوظائف الكاملة** التي طلبتها، لكن على مكدس تقني أبسط وأسرع في الاختبار الفعلي بدلًا من الوعد بمكدس ضخم دون اختبار حقيقي:

| ما طلبته | ما تم بناؤه فعليًا وتم اختباره |
|---|---|
| Next.js + React + TypeScript | HTML/CSS/JS عادي (بدون إطار عمل) — أسرع تحميلًا لشاشات المحطات، لا يحتاج بناء (build step) |
| NestJS / PostgreSQL | Node.js + Express + SQLite (وحدة `node:sqlite` المدمجة في Node، بدون تثبيت أي محرك خارجي) |
| MQTT | REST API + WebSocket (Socket.io) — نفس تجربة التحديث اللحظي |
| Docker | غير مضمّن حاليًا (المشروع Node.js عادي، يمكن إضافة Dockerfile لاحقًا بسهولة) |
| Google Maps / Mapbox | OpenStreetMap + Leaflet (مجاني بالكامل، لا يحتاج مفتاح API) |

**كل ميزة وظيفية طلبتها موجودة وتعمل**: 10 حافلات حية، خريطة ثنائية اللغة، لوحة إدارة بـ 5 أدوار، تطبيق سائق، بلاغات، تنبيهات، إعلانات، سجل تدقيق، تقارير قابلة للتصدير. الفرق فقط في التقنية الأساسية تحتها. إذا أردت لاحقًا الانتقال إلى PostgreSQL/Next.js/Docker فعليًا، يمكن ذلك كمرحلة تالية.

## التشغيل السريع (تجربة محلية)

```bash
npm install
npm run seed        # يضيف: 12 محطة، 3 مسارات، 10 حافلات، 10 سائقين، 5 حسابات دخول
npm start           # يشغّل السيرفر على http://localhost:3000
```

في نافذة طرفية أخرى، لتشغيل **وضع المحاكاة** (Simulation Mode) الذي يحرّك الحافلات العشر تلقائيًا دون أجهزة GPS حقيقية:

```bash
npm run simulate
```

افتح `http://localhost:3000` وسترى الحافلات العشر تتحرك لحظيًا على الخريطة.

> **ملاحظة:** المشروع يستخدم وحدة `node:sqlite` المدمجة في Node.js، لذا يلزم **Node.js نسخة 22.5 أو أحدث** (بدون أي تثبيت لقاعدة بيانات خارجية).

## ربط أجهزة GPS حقيقية

كل حافلة لها `device_key` فريد (تراه في تبويب **المركبات** بلوحة الإدارة). جهاز GPS المثبت في الحافلة (انظر `device/esp32_gps_tracker.ino` لمثال كود ESP32 + وحدة NEO-6M) يرسل طلب POST دوريًا كل 3-10 ثوانٍ:

```
POST /api/gps
{
  "device_key": "DEVICE-KEY-BUS-1",
  "lat": 25.2990, "lng": 55.4785,
  "speed": 22, "heading": 90,
  "battery_level": 85
}
```

بدلاً من جهاز مخصص، يمكن أيضًا استخدام **تطبيق السائق نفسه** (`/driver/app.html`) الذي يشارك موقع الهاتف مباشرة أثناء الرحلة — لا حاجة لجهاز GPS منفصل إذا كان هذا كافيًا لك.

## المزايا المطبّقة (checklist مقابل طلبك الأصلي)

### شاشة العرض العامة ✅
خريطة حية، أيقونات مرقّمة (Bus 1–10)، ألوان مختلفة لكل مسار، المحطة الحالية/القادمة، ETA بالدقائق، حالات الحافلة الست (In Service / Approaching / At Station / Delayed / Out of Service / Emergency)، قائمة جانبية مرتبة حسب الأقرب، شريط إعلانات متحرك، الوقت والتاريخ، تبديل عربي/إنجليزي RTL/LTR، فلترة حسب محطة، رابط مخصص لكل محطة (`/station/:id`)، تحديث تلقائي بدون إعادة تحميل (Socket.io).

### لوحة الإدارة ✅
تسجيل دخول JWT، تغيير كلمة المرور، 5 أدوار (بما فيها السائق)، إدارة كاملة للمركبات (نوع، سعة، صورة، حالة، ربط GPS)، المحطات والمسارات (بناء المسار بترتيب المحطات)، السائقين، متابعة السرعة/الاتصال/البطارية، تنبيهات تلقائية (خروج عن المسار، تجاوز سرعة، توقف غير طبيعي، انقطاع GPS)، إعلانات لشاشات محطات محددة، بلاغات السائقين، سجل تدقيق كامل لكل عملية، تقارير + تصدير CSV (يفتح مباشرة في Excel).

### تتبع GPS ✅
REST API + WebSocket لحظي، وضع محاكاة كامل بدون أجهزة حقيقية، تحديث كل 3 ثوانٍ في وضع المحاكاة (قابل للتعديل).

### تطبيق السائق ✅
تسجيل دخول، اختيار الحافلة، بدء/إنهاء الرحلة، مشاركة/إيقاف الموقع، عرض المسار والمحطة القادمة، بلاغ عطل/ازدحام/حادث/طارئ، إيقاف الحافلة عن الخدمة.

### الأمان ✅
تشفير كلمات المرور (bcrypt)، JWT بجلسات تنتهي بعد 12 ساعة، Rate limiting على تسجيل الدخول، صلاحيات محكمة (403 عند تجاوزها)، سجل تدقيق، عدم كشف device_key في أي واجهة عامة.

### غير مطبّق حاليًا (يمكن إضافته لاحقًا)
- تصدير PDF مباشر (متاح CSV/Excel الآن؛ يمكن إضافة مكتبة PDF لاحقًا)
- Dark/Light mode مستقل للوحة الإدارة (التصميم الحالي فاتح فقط)
- شاشة "Screen Management" لربط كل جهاز عرض فعلي (حاليًا كل شاشة تُفتح بالرابط مباشرة)

## بنية المشروع

```
uni-bus-tracker/
├── server.js              نقطة التشغيل: Express + Socket.io + مهمة كشف انقطاع GPS

├── middleware/auth.js      JWT + الأدوار + Rate limiting
├── middleware/audit.js     تسجيل سجل التدقيق
├── routes/gps.js           استقبال بيانات أجهزة GPS
├── routes/driver.js        واجهة تطبيق السائق

└── public/                 كل الواجهات (index, display, admin, driver)
```

## نشر المنصة على الإنترنت (Render)

1. ارفع محتويات هذا المجلد إلى مستودع GitHub (الملفات مباشرة في الجذر، وليس داخل مجلد فرعي).
2. على render.com: **New → Web Service** → اختر المستودع.
3. Build Command: `npm install` — Start Command: `npm start`.
4. أضف متغيّر بيئة `JWT_SECRET` بقيمة عشوائية طويلة (Settings → Environment).
5. بعد أول نشر، افتح تبويب **Shell** ونفّذ `npm run seed`.
6. رابط موقعك سيكون شيئًا مثل `https://your-app.onrender.com`.

للحصول على وضع Kiosk حقيقي على شاشة محطة: افتح `https://your-app.onrender.com/station/1` في متصفح الشاشة واضبطه على وضع ملء الشاشة (F11 أو Kiosk mode من إعدادات الجهاز/المتصفح).
